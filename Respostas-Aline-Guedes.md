##
1. Qual a diferença entre `git init` e `git clone`?

R- O git init cria um repositório novo localmente, enquanto o git clone copia um repositório já existente com todo o seu histórico.

2. O que faz o comando `git status`?

R- O comando git status mostra o estado actual dos ficheiros, indicando alterações, staging e itens não rastreados.

3. Para que serve o `git add` antes do `git commit`?

R- O git add prepara alterações para o commit, permitindo controlar exactamente o que será registado.

4. Qual a diferença entre `git pull` e `git fetch`?

R- A diferença entre git fetch e git pull é que o primeiro apenas descarrega alterações do remoto, enquanto o segundo também as integra no código local.

5. O que é um branch e por que ele é usado?

R- Um branch é uma linha de desenvolvimento separada, usada para trabalhar de forma isolada sem afectar a base principal.

6. O que é um Pull Request no GitHub?

R- Um Pull Request é um pedido para integrar mudanças de uma branch noutra, normalmente com revisão antes da aprovação.

7. Explique a diferença entre branch de origem e branch de destino em um PR.

R- No PR, a branch de origem contém as alterações e a de destino é onde elas serão aplicadas.

8. O que acontece se duas pessoas alterarem a mesma linha de um arquivo em branches 
diferentes?

R- Se duas pessoas alterarem a mesma linha em branches diferentes, ocorre um conflito que precisa de resolução manual.

9. Para que serve o arquivo `.gitignore`?

R-O ficheiro .gitignore define o que não deve ser versionado.

10. Qual é a função do `README.md` em um projeto?

R- O README.md serve para documentar o projecto e orientar quem o utiliza
